================================================================================
                           CANOPYGUARD WORKFLOW GUIDE
================================================================================

This document details the project structure, technologies, user workflows, 
roles, and technical processes within the CanopyGuard (TreeCanopy) application.

--------------------------------------------------------------------------------
1. PROJECT OVERVIEW AND TECHNOLOGIES
--------------------------------------------------------------------------------
CanopyGuard is a web application structured with a decoupled frontend and backend.

[Frontend Details]
- Framework: React 19 with Vite 
- Key Dependencies: React Router DOM, Leaflet (Maps integration), SweetAlert2, 
  Lucide React (Icons), React OAuth Google.
- Architecture: Supports three distinct environments/entry points:
  * Citizen Portal (run via `npm run dev:citizen`)
  * Tree Cutter Portal (run via `npm run dev:cutter`)
  * Admin/Official Portal (run via `npm run dev:admin`)

[Backend Details]
- Framework: Node.js with Express 5
- Database: MongoDB using Mongoose
- Key Dependencies: 
  * Cloudinary & Multer (Image/photo uploads for reports and task progress)
  * Razorpay (Payments/equipment purchasing for cutters)
  * JSON Web Tokens (JWT) & Google Auth Library (Authentication)
  * BcryptJS (Password hashing)
  * Nodemailer (Email notifications)

--------------------------------------------------------------------------------
2. ROLES AND ACCESS CONTROL
--------------------------------------------------------------------------------
The system supports four primary user roles, each with designated entry points
and dashboard access:

- Citizen (Public User):
  * Entry point: /citizen-dashboard
  * Purpose: Report tree issues (hazardous trees, pruning requests), track issue
    resolution progress, view local tree statistics, and access the Tree Encyclopedia.

- Tree Cutter (Arborist / Field Specialist):
  * Entry point: /task
  * Purpose: View assigned cutting tasks, mark daily attendance, manage/purchase
    equipment (integrated with Razorpay), and execute field operations using 
    the step-by-step task wizard.

- Official (Municipal Supervisor):
  * Entry point: /dashboard
  * Purpose: Review citizen-reported complaints, schedule tasks, dispatch work
    orders to tree cutters, monitor field attendance, and manage tree inventories.

- Admin (System Administrator):
  * Entry point: /admin
  * Purpose: System configuration, full database access, user management, and advanced
    inventory audits.

--------------------------------------------------------------------------------
3. COMPLAINT & REPORTING WORKFLOW (Citizen)
--------------------------------------------------------------------------------
1. Registration & Login:
   * Citizen registers on /register and logs in via /login (Standard or Google Auth).
2. Reporting an Issue:
   * Citizen navigates to /report-issue (Report Tree Issue).
   * Fills out details: tree species (if known), location description, severity,
     urgency level, and uploads photos (processed via Cloudinary).
   * On submit, a complaint record is generated in the database (via POST /api/complaints).
3. Tracking the Report:
   * Citizen is redirected to /track or can view their reports under /citizen-dashboard.
   * Shows status: "Reported" -> "Assigned" -> "In Progress" -> "Work Completed" -> "Closed".

--------------------------------------------------------------------------------
4. DISPATCH & SCHEDULING WORKFLOW (Official)
--------------------------------------------------------------------------------
1. Reviewing Complaints:
   * Official logs in, landing on /dashboard, showing global KPIs (Active Reports,
     Pending Dispatches, Cutters on Duty).
   * Navigates to the Inbox to review incoming citizen complaints.
2. Scheduling & Assignment:
   * Official opens the Scheduler (/scheduler) or assigns directly from a complaint.
   * Selects an arborist/cutter, schedules a due date, sets priority, and creates
     a formal Work Order / Task (via POST /api/trees/tasks or similar).
   * The status updates from "Reported" to "Assigned" / "Scheduled".

--------------------------------------------------------------------------------
5. FIELD EXECUTION WORKFLOW (Tree Cutter)
--------------------------------------------------------------------------------
Once a task is dispatched, the assigned Tree Cutter logs in and navigates to the
Work Orders board (/task). The task follows a strict 3-step field workflow:

- Step 1: Site Arrival & Initial Proof
  * Action: The cutter arrives on-site and clicks "Confirm Site Arrival".
  * Proof: Cutter uploads a photo of the tree/site *before* starting work.
  * Backend: Logs arrival timestamp and captures GPS coordinates (status: Reached Location).

- Step 2: Tree Cutting/Pruning Work
  * Action: Cutter clicks "Start / Mark Work In Progress" (status: In Progress).
  * Proof: Cutter must upload a progress photo (ongoing trimming/cutting) and
    an after-work photo (completed condition).
  * Backend: Saves photos, updates task progress percentage. Clicking "Mark Work
    Completed" transitions the status to Work Completed.

- Step 3: Waste Disposal & Final Sign-Off
  * Action: Cutter inputs estimated green waste volume (m³) and selects one of
    the government-approved dumping sites.
  * Proof: Uploads final disposal confirmation photo.
  * Backend: Submits final verification (via POST /api/trees/tasks/:id/dispose),
    notifies the official, and sets the status to Waste Disposed / Ready for Closure.

--------------------------------------------------------------------------------
6. UTILITY WORKFLOWS
--------------------------------------------------------------------------------
- Attendance Marking:
  * Tree Cutters must mark attendance via /attendance by performing biometric or
    GPS-verified check-in/check-out.
  * Stored in the attendance collection (via POST /api/attendance/check-in).
- Equipment Management:
  * Tree Cutters can view available equipment inventory or purchase gear via /property-inventory
    and /purchase-equipment (integrated with Razorpay backend).
- Tree Encyclopedia:
  * All users can browse the Tree Encyclopedia (/tree-encyclopedia) to read about
    protected tree species, pruning regulations, and conservation guidelines.
--------------------------------------------------------------------------------
7. FUNCTIONAL REQUIREMENTS
--------------------------------------------------------------------------------

7.1 Citizens Module (/citizen-dashboard, /eco-store)
- Registration & Authentication: Allows citizens to create an account by providing name, mobile number, address, email, and password, or register using Google OAuth.
- Login: Verifies credentials (or Google tokens), issuing JWT tokens for session access across citizen endpoints.
- Profile Management: Displays citizen profile details, Eco-Point balances, reported issue history, and past store orders.
- Raise Complaints (/report-issue): Enables reporting of black spots or tree hazards by uploading photos (Cloudinary), selecting urgency levels, providing text descriptions, and fetching latitude/longitude via browser geolocation or Leaflet map picking.
- Track Status & Complaint Details (/track): Displays real-time status tracking for reported issues across a 5-stage progress pipeline (Reported -> Assigned -> In Progress -> Work Completed -> Closed) with timeline details and proof photos.
- Green Marketplace & Digital Gate Pass (/eco-store): Allows citizens to browse eco-products (compost, mulch, biochar, saplings), add items to cart, select home delivery or yard self-pickup, pay via Razorpay or redeem Eco-Points, and view/download a QR code digital gate pass for pickup verification.

7.2 Admin & Official Module (/dashboard, /scheduler, /timber-management)
- Administrative Authentication: Secure login for BBMP officials and system administrators to access global analytics, management panels, and scheduling boards.
- Executive Dashboard & Reports: Displays global KPIs (Active Reports, Pending Dispatches, Cutters on Duty, Biomass Volumes), ward-wise metrics, and official performance logs.
- Complaint & Dispatch Management (/scheduler): Allows administrators to review citizen complaints, assign tasks to field arborists/cutters, set priority levels, assign target completion dates, and reassign work orders.
- User & Field Staff Oversight: Manages registered citizens, tree cutters, yard supervisors, and timber merchants; includes viewing attendance logs and equipment requests.
- Masters & Geographic Setup: Configures geographic zones, divisions, wards, and designated municipal processing yards/dumping depots.
- Official Timber Salvage Management (/timber-management): Monitors timber inventory, converts weighbridge intake logs into commercial auction lots, sets reserve prices, tracks active bidding, awards lots, and issues downloadable Municipal Allotment Certificates.

7.3 Tree Cutters / Arborists Module (/task, /attendance)
- Login & Attendance Verification (/attendance): Secure authentication enabling field workers to perform GPS/biometric-verified daily check-in and check-out operations.
- Work Orders Board (/task): Displays all assigned field tasks categorized by priority, ward location, and scheduled due date.
- 3-Step Field Execution Wizard:
  * Step 1 (Arrival Proof): Confirms arrival at site and uploads pre-work photo.
  * Step 2 (Work Execution): Updates status to "In Progress", uploads work-in-progress and post-execution photos.
  * Step 3 (Waste Segregation & Disposal): Logs segregated waste weights (Foliage/Leaves, Branches/Twigs, Heavy Wood Logs), tree species, number of logs, average log diameter, vehicle registration details, and uploads disposal proof.
- Equipment & Gear Management (/purchase-equipment): Allows field staff to browse required safety equipment and purchase gear through an integrated Razorpay checkout.

7.4 Processing Yard Module (/processing)
- Weighbridge Intake Verification: Reviews intake submissions logged by tree cutters, verifies weighed biomass loads, and approves incoming biomass for composting or timber salvaging.
- Composting Lifecycle Tracker: Monitors organic waste maturation through 5 distinct stages: Collection -> Shredding/Inoculation -> Aerobic Decomposition (logging temperature & moisture) -> Screening/Curing -> Packaged Yield.
- Retail Store Inventory Management: Converts cured compost yields into packaged products (e.g., 5kg/10kg bags), manages stock levels, sets Rupee and Eco-Point prices, and updates the Citizen Green Store inventory in real time.

7.5 Commercial Timber Salvage Auction Module (/timber-auction)
- Commercial Merchant Registration: Enables B2B merchants and commercial sawmills to register by submitting company details, GSTIN, Trade License numbers, and authorized contact information.
- Live Auction Bidding Portal: Displays active salvage timber lots with detailed specifications (volume m³, weight kg, wood species, moisture content, grade). Includes live countdown timers, automated bid placement validation, and dynamic "Highest Bidder" / "Outbid" status alerts.
- Allotment Retrieval & Gate Pass: Allows winning bidders to view closed auction results, verify payment fulfillment, and retrieve official municipal gate passes for lot collection.
